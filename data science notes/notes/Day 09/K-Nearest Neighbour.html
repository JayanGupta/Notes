Module 01 // Memory-Based Architecture

What is KNN?

K-Nearest Neighbors (KNN) is a non-parametric, lazy supervised learning algorithm that predicts targets based on topological proximity within an $D$-dimensional vector space.

Unlike parametric frameworks, KNN skips structural parameter updates entirely during training, storing raw instances directly. At inference, it looks up local points to map decision boundaries:

  • Classification: Uses a majority vote across the nearest $K$ points.
  • Regression: Computes the local arithmetic or distance-weighted target mean.

Module 05 // L2 Vector Formulations

05 L2 Formulation: Euclidean Distance

The default standard for geometric proximity is **Euclidean Distance** ($L_2$ Norm), derived directly from the Pythagorean theorem.

It calculates the straight-line distance through multi-dimensional space between a query vector $q$ and a reference vector $p$:

$$d(p, q) = \sqrt{\sum_{i=1}^{n} (p_i - q_i)^2}$$

This metric works best when feature coordinates are continuous, tightly grouped, and directly comparable without massive scale differences.

Module 06 // Vector Space Generalization

06 Generalization: Minkowski Formula

To support advanced vector operations, we use the **Minkowski Distance** formula to generalize our metric calculations.

By adjusting the order parameter $p$, we change how individual dimension differences contribute to the overall distance score:

$$d(p, q) = \left( \sum_{i=1}^{n} |p_i - q_i|^p \right)^{\frac{1}{p}}$$
  • $p = 1$: Resolves to the grid-based Manhattan Distance metric ($L_1$ Norm).
  • $p = 2$: Resolves to the straight-line Euclidean Distance metric ($L_2$ Norm).
  • $p \to \infty$: Resolves to the Chebyshev Distance metric, which looks only at the single largest coordinate difference.

Module 07 // Inference Polling Layer

07 How KNN Predicts

The inference workflow follows a deterministic pipeline during local polling:

  • Step 1: Distance Scans: The model measures the distance from the unclassified query vector to every single training instance across the dataset.
  • Step 2: Proximity Sorting: It ranks all rows by distance score to isolate the closest $K$ vectors.
  • Step 3: Target Consensus: It combines the targets of those neighbors to generate a prediction (using majority voting for classification or averaging for regression).

Module 08 // Boundary Topology Bias

08 Hyperparameters: The Meaning of K

The parameter $K$ controls how many neighbors inform your predictions, directly balancing model bias and variance.

Adjusting $K$ changes the complexity and texture of the decision boundary:

  • Ultra-Low $K$ ($K=1$): Highly complex, jagged decision boundaries. The model responds strongly to local data noise and outliers, increasing variance.
  • Ultra-High $K$ ($K \to N$): Very smooth, simple boundaries. The model collapses toward the global majority class, ignoring local patterns and increasing bias.

Module 09 // Structural Optimization Sweep

09 Optimization: Choosing the Best K

We find the optimal value for $K$ by scanning a range of values using Cross-Validation to look for the lowest generalization error.

This tuning process searches for a sweet spot where the model captures the real underlying signal without overfitting to training noise:

  • Tie Breaking: For binary classification, use odd values for $K$ to prevent deadlocks in majority voting.
  • The $\sqrt{N}$ Rule: A common starting heuristic is to set $K \approx \sqrt{N}$, then adjust based on cross-validation results.

Module 11 // Categorical Probability Mapping

11 Workflow: KNN Classification

In classification tasks, KNN computes local class probabilities based on neighbor proportions:

$$P(Y = c \,|\, X = x_0) = \frac{1}{K} \sum_{i \in \mathcal{N}_0} I(y_i = c)$$

The model can use standard majority voting, or apply distance weights ($w_i = \frac{1}{d_i}$) so that closer neighbors have a larger influence on the predicted class.

Module 12 // Continuous Space Interpolation

12 Workflow: KNN Regression

KNN handles continuous targets by switching from voting to averaging value distributions within the neighborhood.

Instead of continuous curves, it creates localized, non-parametric step patterns across the target landscape:

$$\hat{f}(x_0) = \frac{1}{K} \sum_{i \in \mathcal{N}_0} y_i$$

This approach allows the model to capture non-linear trends fluidly without needing to define complex global equations.

Module 13 // Zero Parameter Lazy Evaluation

13 The "Lazy Learning" Training Profile

KNN uses a **lazy learning** strategy, meaning its training phase has a computational complexity of $\mathcal{O}(1)$.

The training step requires no coefficient updates or gradient descent calculations. Instead, the model simply saves the raw data vectors directly into memory:

  • No Parameter Derivation: Skips long backpropagation training loops completely.
  • Instant Ingestion: Adding new training samples is as simple as saving them to memory, making the ingestion phase incredibly fast.
Training Floating Point Operations (FLOPs):0 Operations (Instant Storage)
Memory Footprint Allocation Profile:Linear Growth Space [O(N)]
Module 14 // Runtime Scalability Bottlenecks

14 Inference Latency & Scalability Challenges

While training is instant, KNN shifts its entire computational burden to the inference phase, leading to an operational bottleneck.

To predict a single query point, a standard brute-force lookup must calculate distances across every single instance ($N$) and feature ($D$) in the dataset:

$$\text{Inference Complexity: } \mathcal{O}(N \cdot D)$$

As your dataset grows into millions of rows, inference times can slow down dramatically, which can limit live real-time deployments.

Module 17 // Comparative Competitive Selection Matrix

Algorithmic Architectural Analysis

Choosing between KNN and alternative models depends on your data size, complexity, and operational constraints:

Instance-Based KNN

Model Formulation: Fully non-parametric. Learns localized step boundaries directly from raw instances without mathematical presuppositions.

Resource Allocation Profile: $\mathcal{O}(1)$ training footprint, but heavy $\mathcal{O}(N \cdot D)$ inference latency and storage requirements.

Handling Complex Structures: Adapts fluidly to highly complex, multi-modal spaces without needing manual feature transformations.

Parametric / Tree Alternatives

Model Formulation: Strict mathematical boundaries. Linear frameworks build flat continuous hyperplanes, while Trees build orthogonal partitions.

Resource Allocation Profile: Heavy upfront training costs ($\mathcal{O}(N \cdot D)$ or worse), but ultra-fast, low-latency inference updates.

Handling Complex Structures: Linear models require manual transformation for non-linear data; trees handle non-linear data well but require structural constraints to prevent overfitting.
