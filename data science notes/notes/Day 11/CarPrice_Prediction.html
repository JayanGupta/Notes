Step 3 — Feature Engineering

Turning Strings into Numbers

ML models need numbers. Raw string columns like Engine contain units that must be parsed out.

Before: Raw Strings

# These columns are type: object Engine: "1198 cc" Max Power: "87 bhp @ 6000 rpm" Max Torque: "109 Nm @ 4500 rpm"

After: Clean Numbers

df['Engine'] = df['Engine'].str.replace(' cc', '').astype(float) df['Max Power'] = df['Max Power'].str.extract(r'([\d\.]+)').astype(float) df['Max Torque'] = df['Max Torque'].str.extract(r'([\d\.]+)').astype(float)
🔬

What is .str.extract()?

Uses a regex pattern to pull the first numeric value from a string. The pattern ([\d\.]+) matches any digit or dot sequence.

Step 5 — Preprocessing

Building the ML Pipeline

📂

1. Select Modeling Features

Keep 8 columns: Year, Kilometer, Engine, Max Power, Seating Capacity, Fuel Type, Transmission, Seller Type. High-cardinality text like Model/Color is simply left out.

🩹

2. Impute Missing Values

Numeric gaps (e.g. Seating Capacity) filled with the median; categorical gaps filled with the most frequent value — both inside the pipeline.

🔢

3. One-Hot Encode Categoricals

Fuel Type, Transmission, Seller Type converted via OneHotEncoder(handle_unknown='ignore', drop='first').

✂️

4. Train/Test Split

80/20 split — 1,588 training rows / 398 test rows — via train_test_split() with random_state=42.

from sklearn.pipeline import Pipeline from sklearn.compose import ColumnTransformer from sklearn.impute import SimpleImputer from sklearn.preprocessing import OneHotEncoder numerical_features = ['Year', 'Kilometer', 'Engine', 'Max Power', 'Seating Capacity'] categorical_features = ['Fuel Type', 'Transmission', 'Seller Type'] numerical_transformer = Pipeline(steps=[ ('imputer', SimpleImputer(strategy='median')) ]) categorical_transformer = Pipeline(steps=[ ('imputer', SimpleImputer(strategy='most_frequent')), ('onehot', OneHotEncoder(handle_unknown='ignore', drop='first')) ]) preprocessor = ColumnTransformer(transformers=[ ('num', numerical_transformer, numerical_features), ('cat', categorical_transformer, categorical_features) ])

💡 sklearn Pipeline: Wraps preprocessor + model into one object, fitting imputers and the encoder only on training data. No manual scaling is used — Random Forest doesn't need it.

Step 6 — Modelling

Weak Baseline vs Random Forest

To showcase the performance difference, two pipelines are trained: a simple Linear Regression baseline and a Random Forest — an ensemble of decision trees whose final prediction is the average of all tree outputs.

from sklearn.linear_model import LinearRegression from sklearn.ensemble import RandomForestRegressor lr_pipeline = Pipeline(steps=[ ('preprocessor', preprocessor), ('model', LinearRegression()) ]) rf_pipeline = Pipeline(steps=[ ('preprocessor', preprocessor), ('model', RandomForestRegressor( n_estimators=100, random_state=42 )) ]) lr_pipeline.fit(X_train, y_train) rf_pipeline.fit(X_train, y_train)

🌲 How Random Forest Works

  • Build 100 independent decision trees
  • Each tree sees a random sample of data (bootstrap)
  • Each split considers random subset of features
  • Average all tree predictions → robust result

🎯 Why Compare the Two?

  • Linear Regression assumes straight-line relationships
  • Car pricing is non-linear and heavily skewed
  • Random Forest handles that non-linearity naturally
  • Robust to luxury-car outliers left in the data
  • Comparison quantifies exactly how much that buys us

Understanding Metrics

Regression Evaluation Metrics

R² Score

1 - (SS_res / SS_tot)

Measures how much of the variance in the target the model explains. 1.0 = perfect, 0 = no better than mean.

RF: 0.74  ·  LR: 0.54

MAE

mean(|y_pred - y_true|)

Average absolute difference between prediction and reality. In the same units as target (₹). Intuitive and robust to outliers.

In Action

Handling Unseen Categories

When the model transforms the test set, it can meet category values it never saw during training. handle_unknown='ignore' is what keeps the pipeline from crashing.

Actual warning raised while scoring the test set:

UserWarning: Found unknown categories in columns [0] during transform. These unknown categories will be encoded as all zeros.

Why it happens & why it's safe

🔀 Random split, rare category

With an 80/20 split, a rare value of a categorical column (e.g. a seller-type variant) can land only in the test fold and never appear in training.

🛡️ Graceful degradation

OneHotEncoder(handle_unknown='ignore') encodes the unseen category as all zeros instead of raising an error — the pipeline keeps predicting.

🚀 Production implication

This is exactly the behavior you want in a deployed API: a brand-new seller type from a live listing shouldn't take the whole service down.

Summary

🎓 Key Takeaways

1

Feature Engineering is Everything

Raw strings (Engine: "1198 cc") must be parsed into numbers before ML can use them. Domain knowledge guides what to extract and how.

2

Smart Missing Value Strategy

Not all NaN values should be dropped or filled the same way. EVs have 0 engine specs by design — applying domain knowledge prevents data loss.

3

sklearn Pipelines Prevent Leakage

Fitting imputers and the one-hot encoder inside a Pipeline ensures they only learn from training data. This is critical for valid evaluation and deployment safety.

4

Technical Specs Dominate Price

Correlation analysis shows Max Power (+0.78), Max Torque (+0.67), and Engine size (+0.61) are the strongest numeric predictors — far ahead of Kilometer (−0.15).

🏆

Pipeline Complete!

We built an end-to-end ML pipeline that predicts used car prices with R² = 0.74 and a mean error of ₹3.78 Lakhs — more than double the Linear Regression baseline's explanatory power.
