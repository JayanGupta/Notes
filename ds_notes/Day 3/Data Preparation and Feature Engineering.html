The Preprocessing Pipeline

Raw data files are filled with inconsistencies, missing records, and unoptimized data types. Forcing raw vectors into high-variance estimators will yield inaccurate models.

We decouple our preprocessing workflow into two primary architectural blocks:

  • Phase 1: Data Cleaning — Remedying structural gaps, unstandardized features, duplicates, and extreme variance distortions.
  • Phase 2: Feature Engineering — Creating highly predictive structural attributes from raw text, encoding categoricals, and optimizing scale.

The Preprocessing Continuum

1. Data Cleaning Phase

Handles incomplete matrices (Age/Cabin), isolates structural anomalies, and drops duplicate vectors.

2. Feature Engineering Phase

Unpacks social dimensions from text strings, builds descriptive markers, maps categoricals, and applies normalization matrices.

Handling Missing Values

Real-world datasets often arrive with missing observations. Optimization engines require complete matrices to run linear and non-linear calculations.

  • Age: 177 missing entries. Highly informative attribute; dropping row vectors causes severe information loss. We implement Median Imputation.
  • Cabin: 687 missing entries (~77% null density). Imputing would introduce systemic bias. The standard approach is dropping the column structural array.

Inconsistencies, Types & Duplicates

Production-level pipelines consolidate records containing manual structural inconsistencies, irregular encoding classes, and matching entry faults.

  • Fixing Inconsistent Strings: Overlapping categorization markers (e.g., mixing "male", "MALE", "m") must be normalized into flat classes.
  • Data Type Corrections: Categorical attributes imported as string objects or floating points must be downcast to concrete, low-overhead numeric types.
  • Removing Duplicates: Stripping out exact identical data logs to protect optimization models from data leakage risks.

Outlier Basics

Extreme values distort data distributions and bias standard variance metrics. While typical Titanic tickets cost under $30, luxury suites topped $512.

We quantify and flag structural outliers using the robust Interquartile Range (IQR) rule:

Upper Boundary = Q3 + (Multiplier × IQR)

Creating New Features

Feature engineering builds new structural insights by isolating hidden dimensions inside sparse data strings.

  • FamilySize Engineering: Rather than forcing a model to parse sibling counts (SibSp) and parent records (Parch) independently, we consolidate them: FamilySize = SibSp + Parch + 1
  • Social Rank Engineering: Parsing raw text markers to isolate demographic groupings (e.g., mapping "Braund, Mr. Owen Harris" into discrete feature bins).

Encoding Categorical Variables

Machine learning estimators model quantitative dimensions. String tracking attributes like Sex or Embarked port locations must be transformed into algebraic arrays.

  • Label Encoding: Directly maps text attributes to flat integers (e.g., Male → 1, Female → 0). This approach works well for binary dimensions.
  • One-Hot Encoding: Unpacks multi-class arrays into dedicated binary column features, preventing distance calculations from assuming an unintended numeric order.

Feature Scaling Basics

Distance-based algorithms can become heavily biased when processing attributes with disparate numerical scales. In our dataset, Age ranges from 0.42 to 80, while Fare extends from 0 to 512.

Scaling projects these features onto matching numerical scales so they receive equal weight during model training.

  • MinMax Scaler: Compresses distributions into absolute fixed boundaries of [0, 1].
  • StandardScaler: Centers distributions around a mean of 0 with a unit standard deviation of 1.

Feature Selection Intuition

Feeding every available column into an estimator adds predictive noise and causes overfitting. Good feature selection involves filtering out uninformative attributes to keep the model focused and efficient.
